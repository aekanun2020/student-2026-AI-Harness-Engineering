## คำตอบ (verbatim)

ถูกส่วนหนึ่งครับ แต่มีจุดที่ต้องแยกให้ชัดสองเรื่อง

### 1. คำว่า "raise" ไม่ตรงกับที่โค้ดทำจริง

โค้ดใน `calculate()` **ไม่ได้ raise exception ให้ LLM เห็น** — มัน **ดัก (catch) exception แล้วแปลงเป็น string** ก่อนส่งกลับ:

```python
def calculate(expression: str) -> str:
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "error: อนุญาตเฉพาะตัวเลขและ + - * / ( )"   # validation ธรรมดา ไม่ใช่ exception เลย
    try:
        return str(eval(expression, {"__builtins__": {}}, {}))
    except Exception as e:
        return f"error: {e}"   # ดัก exception ไว้ แปลงเป็น string ก่อนคืนออกไป
```

LLM **ไม่เคยเห็น Python exception จริงๆ เลย** — สิ่งที่ LLM เห็นคือข้อความธรรมดาใน `role: "tool"` message (เหมือนข้อความอื่นๆ ในบทสนทนา) การออกแบบนี้ตั้งใจเลยว่า **ห้ามให้ exception ดิบหลุดออกไปทำให้ loop crash** — ต้องแปลงเป็น text ที่ปลอดภัยก่อนเสมอ

### 2. ข้อความ error ชัดเจน ≠ โมเดลจะแก้ตัวเองได้เสมอ (พิสูจน์แล้วจากการทดสอบก่อนหน้า)

ส่วนนี้คือจุดที่คำกล่าวอ้างยังไม่ครบ — ข้อความ error ที่ชัดเจน (`"error: อนุญาตเฉพาะตัวเลขและ + - * / ( )"`) เป็นเงื่อนไข**จำเป็น**ให้ LLM "เข้าใจ" ได้ก็จริง แต่**ไม่ใช่เงื่อนไขที่เพียงพอ**ให้ LLM "แก้ตัวเอง" (retry เอง) — จากการทดสอบจริงก่อนหน้านี้:

```
TOOL_USE calculate({'expression': '5,000+3,000'}) -> error: อนุญาตเฉพาะตัวเลขและ + - * / ( )
[step 2] END_TURN
[answer] ขออภัยครับ ... กรุณาเขียนใหม่โดยไม่ใช้เครื่องหมายจุลภาค เช่น 5000+3000 แทนได้เลยครับ
```

โมเดล**เข้าใจ**ข้อความ error ถูกต้อง 100% (อธิบายสาเหตุและวิธีแก้ให้ผู้ใช้ฟังได้ถูกเป๊ะ) แต่**เลือกไม่ retry เอง** — โยนกลับไปให้ผู้ใช้พิมพ์ใหม่แทน ทั้งที่ loop ยังมีโควตาอีก 5 รอบให้เรียก `calculate("5000+3000")` เองได้เลย

**สรุปคือ:** ข้อความ error ที่ออกแบบมาดี (`calculate()`'s error message) คือ**ส่วนที่ทำให้ "เข้าใจ" เกิดขึ้นได้จริง** ✅ แต่ **"แก้ตัวเองได้" เป็นคนละเรื่องกัน** — มันต้องการ**คำสั่งเพิ่ม** (เช่นใน `SYSTEM` prompt หรือ hook ที่ `pre_llm`) บอกโมเดลตรงๆ ว่า "ถ้า tool คืน error ให้ลองแก้ argument แล้วเรียกใหม่ก่อนถามผู้ใช้" ซึ่ง Lab 3 **ไม่มีคำสั่งแบบนี้อยู่เลย** — เพราะงั้นแม้ error message จะออกแบบมาดีแค่ไหน โมเดลก็ยังเลือกไม่ retry เองอยู่ดีถ้าไม่มีคำสั่งบอกให้ทำแบบนั้น

พูดให้ตรงคือ: **error surface design ทำให้ "เข้าใจ" ได้ แต่ "แก้ตัวเอง" ต้องมี instruction เพิ่มอีกชั้นหนึ่งที่ Lab 3 ยังไม่มี**

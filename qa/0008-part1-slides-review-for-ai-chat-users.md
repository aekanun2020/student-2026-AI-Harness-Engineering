### ส่วน 1.1 — LLM

**p.2 จุดประสงค์การเรียนรู้** — คำว่า harness, environment, tool, budget/trace ยังไม่ถูกนิยาม ผู้เรียนอ่านแล้วไม่รู้ว่าจะได้อะไร
> เสนอเพิ่มบรรทัดท้าย: *"(คำว่า harness, tool, trace จะค่อย ๆ อธิบายทีละตัว ยังไม่ต้องรู้ตอนนี้)"*

**p.4 LLM คืออะไร** — "ฟังก์ชันทางคณิตศาสตร์" เป็นนามธรรม และไม่ได้โยงกับสิ่งที่ผู้เรียนเคยทำ
> เสนอเพิ่ม: *"prompt = ข้อความที่คุณพิมพ์ในช่องแชท, text ที่ส่งออก = คำตอบที่เห็นบนจอ — ตัวโมเดลแท้ ๆ ทำแค่นี้ ส่วนที่เหลือของแอปแชท (จำบทสนทนา ค้นเว็บ) คือของที่ *ห่อ* รอบโมเดลอีกที ซึ่งเป็นสิ่งที่คอร์สนี้จะสร้าง"*

**p.5 ข้อจำกัดของ Pure LLM** — **จุดเสี่ยงสูงสุด** "ไม่มี Memory" ขัดกับประสบการณ์ที่แชทจำเรื่องก่อนหน้าได้
> เสนอเพิ่มใต้ bullet แรก: *"แต่ ChatGPT จำได้นี่? — ที่จำได้เพราะแอปส่งประวัติแชททั้งหมดกลับไปให้โมเดลอ่านใหม่ทุกครั้งที่คุณกดส่ง ตัวโมเดลเองไม่ได้จำ"*
> ศัพท์: Stateless = "เริ่มใหม่จากศูนย์ทุกครั้ง", Call = "การส่งคำถามไป 1 ครั้ง", Real-time = "ข้อมูลสด ณ ตอนนี้ เช่น ราคาหุ้นวันนี้"

**p.6 DEMO 1: Inference** — คำว่า Inference ไม่มีคำอธิบาย
> เสนอ: *"Inference = การให้โมเดลสร้างคำตอบ 1 ครั้ง (สิ่งที่เกิดขึ้นทุกครั้งที่คุณกดส่งในแชท)"*

**p.7 การเข้าถึง Pure LLM** — หน้าที่หนักที่สุดของช่วงแรก: HTTP API, JSON, metadata, stop_reason, usage, Self-hosted, Token IDs, Tensor, Decode, Model Broker, Normalize, Schema มาพร้อมกันหมด และมีข้อความ *"[ตำแหน่ง D ตามภาพ ...]"* อ้างถึงภาพที่ไม่มีบนสไลด์
> เสนอเพิ่มกล่องศัพท์ 1 กล่อง: *"API = ช่องทางให้โปรแกรมคุยกับโมเดลแทนคนพิมพ์ | JSON = รูปแบบข้อความที่มีช่อง 'ชื่อ: ค่า' ให้โปรแกรมอ่านง่าย | Token = ชิ้นส่วนของคำที่โมเดลนับเป็นหน่วย (ใช้คิดเงิน) | stop_reason = เหตุผลที่โมเดลหยุดพิมพ์ | usage = ใช้ไปกี่ token"*
> และเสนอลบหรือแทนที่ *"[ตำแหน่ง D ตามภาพ...]"* เพราะไม่มีภาพประกอบให้ดู

**p.10 SDK [1/2]** — "Resp object", decoder/tokenizer, serving layer, typed object, `resp.choices[0].message` — ผู้เรียนไม่รู้ว่า SDK คืออะไรตั้งแต่แรก
> เสนอเพิ่มบรรทัดนำ: *"SDK = ชุดโค้ดสำเร็จรูปที่ผู้ให้บริการทำไว้ ให้เราเรียกโมเดลจากโปรแกรมได้โดยไม่ต้องเขียนเอง | resp = 'ซองคำตอบ' ที่ส่งกลับมา ข้างในมีทั้งข้อความและข้อมูลกำกับ"*
> และสรุป 4 bullet เป็นสายเดียว: *"โมเดลให้ตัวหนังสือ → เซิร์ฟเวอร์ห่อเป็น JSON → SDK แกะเป็น object → โค้ดเราหยิบเฉพาะข้อความออกมา"*

**p.11 SDK [2/2]** — bullet 1 บอก "ขึ้นอยู่กับยี่ห้อ SDK" แต่ bullet 3 บอก "ไม่ใช่ยี่ห้อ" ผู้เรียนใหม่จะรู้สึกว่าขัดกัน และ "endpoint" ไม่มีนิยาม
> เสนอแก้ bullet 1: *"ชื่อฟิลด์ขึ้นอยู่กับ 'endpoint ที่เราต่อ' (ที่อยู่ปลายทางที่โค้ดส่งคำขอไป) — ต่อแบบ OpenAI ได้ choices/finish_reason, ต่อแบบ Anthropic ได้ content/stop_reason"*
> เสนอเพิ่มตัวอย่าง: *"เช่น เรียก Claude ผ่าน OpenRouter ก็ได้ฟิลด์หน้าตาแบบ OpenAI — ยี่ห้อโมเดลไม่ใช่ตัวกำหนด"*

### ส่วน 2.3 — Agent & Agent Loop

**p.16 Agent vs Chatbot** — quote ภาษาอังกฤษ และผู้เรียนที่เคยเห็น ChatGPT ค้นเว็บจะคิดว่า "แชทที่ใช้อยู่ก็เป็น agent แล้วนี่"

**p.18 Harness [1/2]** — "Context: ข้อมูลการสนทนา, Tool Name, ..." เป็นรายการโดยไม่มีภาพรวม
> เสนอ: *"Context = ทุกอย่างที่โมเดล 'มองเห็น' ตอนตอบ — เหมือนหน้าจอแชททั้งหมดที่เลื่อนขึ้นไปดูได้ รวมชื่อ tool และผลจาก tool ด้วย"*

**p.19 โค้ด agent_loop.py ทั้งหน้า** — ผู้เรียนที่ไม่เคยเขียนโค้ดจะเห็นเป็นกำแพงตัวอักษร
> เสนอเพิ่มกล่อง "อ่านโค้ดนี้แค่ 5 บรรทัด": *"67 = วนรอบ | 68 = ถามโมเดล | 71 = โมเดลขอใช้ tool ไหม? | 80 = เรียก tool จริง | 89 = ไม่ขอ tool = จบ"*

**p.20 Tool Calling [1/2]** — ประโยคสำคัญ "ร้องขอ ... ผ่านโปรแกรมของนักพัฒนา" ฝังอยู่ในนิยามยาว, Retrieval/Memory/Augmented LLM ไม่มีคำอธิบาย
> เสนอยกขึ้นเป็นประโยคเดี่ยว: *"จำให้ขึ้นใจ: โมเดล 'เขียนใบขอ' ใช้ tool เท่านั้น — โปรแกรมของเราเป็นคนไปทำจริง โมเดลไม่เคยแตะโลกภายนอกเอง"*
> ศัพท์: *Retrieval (ค้นเอกสารมาให้โมเดลอ่าน), Memory (เก็บของจำไว้ข้ามรอบ), Augmented LLM (LLM ที่ถูกเสริมของพวกนี้เข้าไป)*

**p.21 Tool Calling [2/2]** — Input Schema, Request, "Ground Truth" ใช้ในความหมายเฉพาะ
> เสนอ: *Input Schema (แบบฟอร์มบอกว่า tool นี้ต้องการข้อมูลอะไร), Ground Truth (ผลจริงจากโลกภายนอก ไม่ใช่สิ่งที่โมเดลเดา)*

**p.22 static define** — กล่องแดง "**ข้อสังเกต มันคือ static define" ไม่มีคำอธิบาย
> เสนอ: *"static define = รายการ tool ถูกเขียนตายตัวไว้ในโค้ดล่วงหน้า โมเดลเพิ่ม/แก้ tool เองไม่ได้ ใช้ได้เฉพาะที่เราให้"*

**p.23 การตัดสินใจ** — วงเล็บอธิบายสองค่าย (stop_reason vs tool_calls vs finish_reason) รวดเดียว ผู้เรียนใหม่จะจับไม่ทัน
> เสนอย่อเป็น: *"ทั้งสองค่ายสื่อความเดียวกันคือ 'ฉันขอใช้ tool' — Anthropic บอกผ่าน stop_reason, OpenAI บอกผ่านการมี tool_calls"*

**p.24 Loop** — ตารางด้านขวาตัวเล็กมากจนอ่านไม่ออกบนจอฉาย
> เสนอเพิ่มบรรทัดเดียวใต้หัวข้อ: *"ทำซ้ำ: ถามโมเดล → ถ้าขอ tool ก็เรียกให้แล้วส่งผลกลับ → ถามอีก … จนกว่าโมเดลจะไม่ขอ tool"*

**p.25 Claude Code** — ผู้เรียนอาจไม่รู้ว่า Claude Code คืออะไร (ต่างจากแอป Claude)
> เสนอ: *"Claude Code = โปรแกรมของ Anthropic ที่ให้ AI ลงมือเขียนโค้ด/สั่งงานในเครื่องเราได้ — คือ agent ตัวจริงที่ใช้ลูปแบบเดียวกับที่เราเพิ่งเขียน"*
> ศัพท์: *max iterations = จำกัดจำนวนรอบสูงสุด*

**p.26 Budget** — step/token budget, usage
> เสนอ: *"เหมือนโควตาข้อความต่อวันในแอปแชท — แต่เราต้องเป็นคนตั้งและนับเองใน harness"*

**p.27 Trace** — run_id, step, duration, event เป็นศัพท์ระบบ และตัวอย่าง "test ผ่านแต่แก้ผิดไฟล์" เป็นตัวอย่างของนักพัฒนา
> เสนอ: *"trace = บันทึกเส้นทางการทำงานทีละรอบ เหมือนประวัติการสั่งซื้อที่ย้อนดูได้ว่าเกิดอะไรขึ้นตอนไหน"*
> ตัวอย่างแทน: *"tool ทำงานสำเร็จ แต่ผลไม่ตรงโจทย์ — สำเร็จ ≠ ถูก"*

### ส่วน Hooks & Middleware (p.29–37)

**p.30 ปัญหาที่ Hooks แก้** — safety/observability ไม่มีคำอธิบาย
> เสนอ: *"safety (กันไม่ให้ทำสิ่งอันตราย), observability (มองเห็นว่าเกิดอะไรขึ้นระหว่างทาง) — Hook เหมือนจุดตรวจที่วางไว้ก่อน-หลังแต่ละขั้นตอน โดยไม่ต้องรื้อขั้นตอนเดิม"*

**p.32 สองแนวทางจากอุตสาหกรรม** — subprocess, exit code, tripwire, throw exception
> เสนอ: *subprocess/exit code (รันโปรแกรมเล็ก ๆ แยกต่างหาก แล้วดูรหัสผลลัพธ์: 0 = ผ่าน, อื่น ๆ = ไม่ผ่าน), tripwire (สายสะดุด — โดนแล้วหยุดทันที), throw exception (โปรแกรมหยุดพร้อมแจ้งข้อผิดพลาด)*

**p.33 ทำไมเรียกว่า Middleware** — **จุดเสี่ยงสูงสุดในส่วนนี้** อ้างอิง Express, Django, `next()`, short-circuit ซึ่งเป็นความรู้เฉพาะนักพัฒนาเว็บ ผู้เรียนทั่วไปไม่มีพื้นให้เทียบ
> เสนอเปลี่ยนคำเทียบเป็นสากล: *"เหมือนด่านตรวจหลายด่านเรียงกัน แต่ละด่านเลือกได้ 3 อย่าง: ปล่อยผ่าน (allow) / แก้เอกสารแล้วส่งต่อ (modify) / ตีกลับไม่ให้ไปต่อ (deny)"* — เก็บ `next()` ไว้ในวงเล็บสำหรับคนที่เขียนเว็บเป็น

**p.35 ตัวอย่างจริง** — API key, audit trail
> เสนอ: *API key (รหัสลับที่ใช้เข้าถึงบริการ — หลุดแล้วคนอื่นใช้เงินเราได้), audit trail (บันทึกหลักฐานย้อนหลังว่าใครทำอะไรเมื่อไร)*

**p.36 deterministic** — deterministic, regex, system prompt
> เสนอ: *deterministic (ได้ผลเหมือนเดิมทุกครั้ง ไม่ขึ้นกับ "อารมณ์" ของโมเดล), regex (กฎจับรูปแบบข้อความ เช่น "มีตัวเลขไหม"), system prompt (คำสั่งตั้งต้นแบบ Custom Instructions ในแอปแชท — โมเดล *อาจ* ไม่ทำตาม แต่โค้ดบังคับได้แน่นอน)*

## ปัญหาที่มาจาก Lab 3

ทดสอบจริงกับ Lab 3 เดิม (ดู [labs/lab3_agent_loop/QUESTIONS.md](../lab3_agent_loop/QUESTIONS.md))
พบว่า: error message จาก `calculate()` ชัดเจนพอให้โมเดล **"เข้าใจ"** error ได้ถูกต้อง (อธิบายสาเหตุ
ให้ผู้ใช้ฟังได้ถูก) แต่โมเดล **"ไม่ retry เอง"** — เลือกโยนกลับไปถามผู้ใช้แทนที่จะลองแก้ไข argument
(ค่าที่ส่งให้ tool — ในที่นี้คือข้อความสูตรเลข) แล้วเรียก tool ใหม่ด้วยตัวเอง ทั้งที่ loop ยังมีโควตาให้ลองใหม่อีกหลายรอบ

สาเหตุคือ `SYSTEM` ของ Lab 3 ไม่มีคำสั่งบอกให้ทำแบบนั้นเลย — loop มี **OBSERVE** (ป้อน error กลับเข้า
context) สมบูรณ์อยู่แล้ว แต่ไม่มีใครสั่งว่า "เห็น error แล้วให้ทำอะไรต่อ"

## ทางแก้ของ Lab 3a: เพิ่มประโยคเดียวใน `SYSTEM`

`SYSTEM` ตรงนี้คือสิ่งเดียวกับ **Custom Instructions / system prompt** ที่คุณเคยตั้งในหน้าแชท —
Lab นี้แค่เพิ่มกติกาข้อเดียวเข้าไป ไม่ได้แตะโค้ดส่วนอื่นเลย:

```python
SYSTEM = (
    "คุณเป็นผู้ช่วยที่ใช้ tool ได้ ถ้าจำเป็นให้เรียก tool ก่อนตอบ ตอบเป็นภาษาไทย "
    "หากผลลัพธ์จาก tool ขึ้นต้นด้วย 'error:' ให้อ่านข้อความ error แล้วพยายามแก้ไข argument "
    "ตามคำแนะนำนั้น แล้วเรียก tool ใหม่ทันที โดยไม่ต้องถามผู้ใช้ก่อน เว้นแต่ลองแก้แล้วยังไม่สำเร็จ"
)
```

ทุกอย่างอื่น (`TOOLS`, `LOCAL_FUNCS`, `calculate()`, `dispatch()`, โครง `run_agent()`) **เหมือน Lab 3
ทุกตัวอักษร** — นี่คือการแก้ปัญหาด้วยเครื่องมือระดับเดียวกับ Lab 3 เอง (prompt engineering ล้วนๆ)
**ยังไม่ใช้ hook/middleware เลย** (นั่นเป็นเรื่องของ Lab 4)

## ผลทดสอบจริง — เทียบกับคำถามเดียวกันเป๊ะ

รันคำถามเดียวกันกับ Lab 3 ทั้งคู่: `กรุณาคำนวณนิพจน์นี้เป๊ะๆ ตามที่เขียน อย่าปรับรูปแบบ: 5,000+3,000`
(ตั้งใจใส่ comma ที่ whitelist ของ `calculate()` ไม่ยอมแน่ๆ)

**Lab 3 (เดิม) — ไม่ retry:**
```
[step 1] THINK -> ขอเรียก 1 tool
           TOOL_USE calculate({'expression': '5,000+3,000'}) -> error: อนุญาตเฉพาะตัวเลขและ + - * / ( )
[step 2] END_TURN
[answer] ขออภัยครับ ... กรุณาเขียนใหม่โดยไม่ใช้เครื่องหมายจุลภาค เช่น 5000+3000 แทนได้เลยครับ
```

**Lab 3a (ที่นี่) — retry เองจริง:**
```
[step 1] THINK -> ขอเรียก 1 tool
           TOOL_USE calculate({'expression': '5,000+3,000'}) -> error: อนุญาตเฉพาะตัวเลขและ + - * / ( )
[step 2] THINK -> ขอเรียก 1 tool
           TOOL_USE calculate({'expression': '5000+3000'}) -> 8000
[step 3] END_TURN
[answer] ผลลัพธ์คือ 8,000 ครับ
```

สังเกตว่าคำถามมีคำสั่ง **"อย่าปรับรูปแบบ"** อยู่ด้วย — แต่คำสั่งใน `SYSTEM` ที่บอกให้ retry เมื่อเจอ
`error:` ยังทำงานได้ (โมเดลเลือกแก้ไขแล้วอธิบายเหตุผลให้ผู้ใช้ฟังอย่างโปร่งใสแทนที่จะปฏิเสธเฉยๆ)

## ข้อจำกัดของวิธีนี้ (ทำไม Lab 4 ยังจำเป็นอยู่)

การแก้ด้วย `SYSTEM` prompt **ไม่การันตี** — เป็นการ "ขอร้อง" ให้โมเดลทำตาม ไม่ใช่การบังคับด้วยโค้ด:

- โมเดลอาจไม่ทำตามคำสั่งนี้เสมอไป (ขึ้นกับโมเดล/ความยาว context/ประโยคที่ผู้ใช้พิมพ์มาแข่งด้วย)
- ไม่มีการจำกัดจำนวนครั้งที่ retry ได้ — ถ้าโมเดลแก้ไขผิดซ้ำๆ อาจวนจนหมด `max_steps` โดยไม่มีใคร
  หยุดมันอย่างมีเงื่อนไข (ต่างจาก Lab 4 ที่ `require_number_on_stop_hook` จำกัดไว้ชัดเจนด้วยโค้ด
  `stop_retry_used`)
- ไม่มีทาง audit/log ว่า retry เกิดขึ้นกี่ครั้ง เพราะอะไร

นี่คือเหตุผลที่ Lab 4 เพิ่ม **hook/middleware** เข้ามา — เพื่อให้การควบคุมพฤติกรรมแบบนี้เป็น
**deterministic จริง** (การันตีด้วยโค้ด ไม่ใช่แค่ขอร้องผ่าน prompt)

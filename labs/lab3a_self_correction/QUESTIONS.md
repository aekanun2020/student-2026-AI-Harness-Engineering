## คำถามตัวอย่าง (ใช้เปรียบเทียบกับ Lab 3 โดยตรง — คำถามเดียวกันเป๊ะ)

**คำถาม:** `กรุณาคำนวณนิพจน์นี้เป๊ะๆ ตามที่เขียน อย่าปรับรูปแบบ: 5,000+3,000`

| | Lab 3 (เดิม) | Lab 3a (ที่นี่) |
| --- | --- | --- |
| step 1 | `TOOL_USE calculate('5,000+3,000')` → `error: ...` | เหมือนกัน |
| step 2 | `END_TURN` — ถามผู้ใช้แทน | `TOOL_USE calculate('5000+3000')` → `8000` |
| step 3 | — | `END_TURN` — ตอบ 8,000 พร้อมอธิบายว่าแก้ format ให้ |

python labs/lab3a_self_correction/agent_loop.py "กรุณาคำนวณนิพจน์นี้เป๊ะๆ ตามที่เขียน อย่าปรับรูปแบบ: 5,000+3,000"

## แบบฝึกหัดสำหรับผู้เรียน

| # | คำถาม | สิ่งที่ควรสังเกต |
| --- | --- | --- |
| 1 | `ช่วยหารากที่สองของ -16 หน่อย` | `(-16)**0.5` ใน Python ทำให้เกิด `complex` result หรือ error ทางคณิตศาสตร์จริง — ลองดูว่า Lab 3a แก้ไขยังไงเมื่อ error ไม่ได้เกิดจาก syntax แต่เกิดจาก "โจทย์ตอบไม่ได้จริง" (ควรสังเกตว่า retry ซ้ำไปก็ไม่ช่วย เพราะปัญหาไม่ใช่ syntax) |
| 2 | ลองปิดประโยค self-correction ใน `SYSTEM` ชั่วคราว (คอมเมนต์ทิ้ง) แล้วรันคำถามเดิมจากด้านบน | ควรกลับไปมีพฤติกรรมเหมือน Lab 3 เดิม (ไม่ retry) — ยืนยันว่าเป็นประโยคนี้เองที่ทำให้เกิด self-correction ไม่ใช่โมเดลหรือโค้ดส่วนอื่น |
| 3 | ลองคิดคำถามที่ทำให้ `calculate()` error ซ้ำ 2 รอบติด (เช่น ให้ argument ผิดซ้ำๆ ในคำถามเดียว) | สังเกตว่าไม่มีอะไรจำกัดจำนวนรอบ retry เลย ต่างจาก Lab 4 ที่ `require_number_on_stop_hook` จำกัดไว้ชัดเจน — นี่คือข้อจำกัดของวิธี prompt-only ที่ README อธิบายไว้ |

## แบบฝึกหัดต่อยอด

ลองแก้ `SYSTEM` เพิ่มเติมให้บังคับพฤติกรรมอื่นๆ เช่น "ถ้าแก้ไข 2 ครั้งแล้วยัง error ให้หยุดถามผู้ใช้"
แล้วสังเกตว่าคุณต้อง "ขอร้อง" ผ่าน prompt มากขึ้นเรื่อยๆ โดยไม่มีการการันตีเลยสักข้อ — เทียบกับการ
เขียน hook ที่นับจำนวน retry เป็นตัวเลขจริงใน Lab 4 ที่การันตีได้ 100%

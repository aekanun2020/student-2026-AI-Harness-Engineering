## แบบฝึกหัด 1: 🟢 บังคับให้ sandbox ต้องทำงานจริง

```bash
python labs/lab6_sandbox/agent_loop.py "ห้ามคำนวณเองหรือประมาณเองเด็ดขาด บังคับให้เรียก tool calculate ด้วย expression '9999**99999999' ตรงๆ แล้วรายงานผลที่ tool ส่งกลับมาเป๊ะๆ"
```

**บรรทัดที่ต้องมองหา:** `TOOL_USE calculate(...) -> error: sandbox process ถูกยุติ (exit code -24, …)`
**ภายในราว 4 วินาที** — ตัวเลขติดลบใน exit code แปลว่าโปรแกรมลูกถูกระบบฆ่าทิ้ง ไม่ใช่จบเอง แล้ว AI
ยังตอบต่อได้ปกติ (`[answer]` ขึ้น) โปรแกรมไม่ค้าง ไม่ crash

> ถ้า AI ไม่ยอมเรียก tool เลย (ตอบเองว่าเลขใหญ่เกินไป) ลองรันซ้ำหรือเน้นคำว่า "บังคับ" ให้แรงขึ้น —
> เป็น safety ของตัวโมเดลเองที่บางครั้งขวางไว้ก่อน

**ลองเทียบกับ Lab 3 เดิม — ⚠️ ทางเลือก ไม่บังคับ:** คำสั่งเดียวกันแต่ใช้ `labs/lab3_agent_loop/agent_loop.py`
จะคำนวณเลขนี้ในโปรแกรมหลักโดยตรง **terminal อาจค้างเป็นนาที กด Ctrl+C อาจไม่หยุด** (ต้องปิดหน้าต่าง
terminal ทิ้งทั้งอัน) และเครื่องอาจอืดชั่วคราว — ถ้าไม่มั่นใจให้เชื่อผลจากข้อด้านบนแทน ไม่ต้องลอง

## แบบฝึกหัดต่อยอด — 🟡/🔴 สำหรับคนที่เขียน Python ได้แล้ว (ข้ามได้)

1. 🟡 ลองแก้ `SANDBOX_CPU_SEC` ใน `agent_loop.py` ให้สั้นลงมากๆ (เช่น 0.1 วินาที) แล้วดูว่านิพจน์ปกติอย่าง
   `15*4` ยังผ่านไหม หรือถูก kill ไปด้วย (สอนเรื่อง trade-off ระหว่างความปลอดภัยกับ false positive)
2. 🔴 รันบน Linux (เช่นใน Docker container หรือ VM) แล้วเช็คว่า `RLIMIT_AS` ตั้งค่าได้จริงไหม (ต่างจาก
   macOS ที่ตั้งไม่ได้เลย) ลองทำให้ subprocess กิน memory เกิน limit โดยไม่กิน CPU มาก ดูว่า `RLIMIT_AS`
   ดักได้ก่อน `RLIMIT_CPU` ไหม
3. 🔴 ลองเพิ่มการจำกัด filesystem จริง (เช่น รัน subprocess ด้วย working directory ชั่วคราวที่ว่างเปล่า
   หรือใช้ `chroot`/container) เพื่อปิดช่องว่างที่ README บอกไว้ว่ายังไม่ครอบคลุม

> เฉลยเชิงพฤติกรรม ไม่ใช่เฉลยคำตอบตายตัว — ประโยคคำตอบของ AI ต่างกันทุกครั้ง สิ่งที่ต้องตรงคือบรรทัด
> `TOOL_USE … -> error: sandbox process ถูกยุติ` ไม่ใช่ข้อความคำตอบ
